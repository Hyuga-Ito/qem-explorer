# Decisions only the owner can make (QEM Explorer 1.9.0)

These were left open on purpose. Nothing in the release invents them; the placeholders say where they go.

| decision | where it goes | current state | what the release does meanwhile |
|---|---|---|---|
| **License** of the code (and, separately, of the data and figures) | a `LICENSE` file at the root, the `license` field of `pyproject.toml` and `CITATION.cff` | none chosen; the archive ships **without** a license, so by default others may not reuse it | the README says so; third-party licenses of the dependencies are untouched |
| **Authors and affiliation** | `CITATION.cff` (`authors`), `pyproject.toml` (`authors`), README | placeholder "QEM Explorer contributors" | no personal names or e-mail addresses are in the public archive |
| **Security contact** | `SECURITY.md` ("Reporting a vulnerability") | not set | `SECURITY.md` describes the protections and says that a contact is to be added by the owner |
| **Hardware validation run** | `configs/selection/hardware17.yaml`, `QEMX_HW_AUTHORIZE` | prepared as a dry run for the 1.8.0 default bundle (`reports/selection_v180/hardware_plan/`: 28 jobs, 524 s of the 540 s window, digest `6015610c337d89a3…`), not executed | `hardware plan` writes the plan and its digest; execution is refused without the owner's authorization of that digest, a campaign ledger (one shared 600 s ceiling, 60 s reserve by default) and credentials from the environment, a saved account or a hidden prompt |
| **Running the next development study** (`fulldev19`) and, once, the reserved confirmation (`conf19`) | `python -m qemx.selection pipeline configs/pipelines/fulldev19.yaml --out runs/fulldev19 --workers auto`; `confirm configs/selection/conf19.yaml …` after the freeze | planned, not executed (the instructions for 1.9.0 excluded the full study). Measured estimate: 3.0–9.3 CPU-hours of labels for fulldev19 (two measured bases; conditional), 0.8–2.4 for conf19; the coherent `chi` tasks are unmeasured; analysis time **unknown** — 4× the pilot's model fits, 51× its fits × training rows (1.9.1): time `analyze --splits same-distribution --extras=` after labeling. conf19's population (five families, no QFT/BV/Grover) and size are yours to decide (options A–C, `docs/selection/RESEARCH_PLAN_v19.md`) | `plan --measured` reports the estimate and the caps (fulldev19: `limits.cpu_hours: 60`, `disk_gb: 20`, `min_free_disk_gb: 5`; conf19: 30, 10, 5); the freeze checklist before conf19 is in `docs/selection/RESEARCH_PLAN_v19.md`; the meaningful effect size that fixes conf19's number of circuits is yours to state (experiment 1 in `docs/RESEARCH_FINDINGS_AND_NEXT_STEPS.md`) |
| **Publishing** (GitHub repository, Streamlit Community Cloud, Zenodo; tags) | — | nothing was pushed, tagged or published. The GitHub `main` is still 1.7.0 (tags `v1.5.0`, `v1.7.0`); 1.8.0 was never pushed, so it has no GitHub Actions run, and neither has 1.9.0. Whether to push 1.9.0 directly (with a `v1.9.0` tag) or 1.8.0 first (with `v1.8.0`) is your choice | the source ZIP is GitHub-ready (one root folder, no credentials, runs or private material); the update procedure is in `docs/RELEASE_CONSISTENCY.md`; the trial-data ZIPs are meant for release attachments (`reports/TRIAL_ATTACHMENTS.json` maps each to its study, and the optional CI job verifies the study it is given); the private audit ZIP is for you only |
| **Which bundle the app ships as default** | `qemx/selection/bundles/` | four bundles are shipped: `qemx-rec-1.8.0` (the frozen configuration; simulator-only features, needs `--allow-simulation`), `qemx-rec-1.8.0-deployable` (deployable features, never simulates) and the two 1.7.0 bundles | the app and `recommend` preselect `qemx-rec-1.8.0-deployable` (it sorts first; no validated selective threshold, so it returns the model's first verified candidate): its full deployed policy is −0.084 [−0.179, −0.002] against SBS-B on the 1.8.0 confirmation, an interval that excludes 0 only marginally; the frozen bundle is the configuration whose full policy the confirmation established (−0.144 [−0.231, −0.076]) but costs an exact simulation per circuit (≈ 0.65 s at 3–6 qubits, exponential in width). Making the frozen bundle the default would also mean allowing simulation by default |
| **Whether the 1.6.0 pilot data stay in the public archive** | `reports/selection_pilot/` | kept as the historical dataset (fixed-shared designs) beside the corrected pilot; its per-trial arrays and figures are omitted from the 1.7.0 source archive (size) and remain in the repository and the 1.6.0 archive | labelled historical in the app and in RESULTS |
| **The historical 1.8.0 figure note with the inverted primary/secondary wording** | `reports/selection_v180/figures/supp_deployment_policy.md` | kept unchanged as the record of the 1.8.0 release; the corrected note and figures are in `reports/corrections_v190/` and the errata in `docs/selection/ERRATA_v180.md` | the 1.9.0 generator writes the corrected text; replacing the historical file (and its digest in the study manifest) is yours to decide |
| **Publishing the pilot19 per-trial arrays** | release attachment `qem-explorer-1.9.0-trials-pilot.zip` | prepared, not published | the source archive carries the pilot's tables, records and checksums (`reports/pilot_v190/`); the arrays are a separate archive |
